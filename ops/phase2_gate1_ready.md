## 已在 CPU 上验证的

- 训练 runner 的 dry-run：6 个 run 全部通过（数据 sha256 与 manifest 一致；lr 1e-5、warmup 10、1 × 16、250 步，与 B_warm-SFT 一致）。
- 评估入口用两种桩生成器把 6 个 run 的整条流水线跑通（oracle：永远给金标；mixed：按题哈希分成金标 / 循环 / 答错），判读脚本读得进、报得出。
  - oracle 桩：准确率与解析正确率 1.000、移植 0.000（读了供体推导的 order 行）、判读 R1——与构造一致。
  - 桩的结果本身没有意义，只证明管道通。
- 流水线测试中发现并修正的两处（均发生在任何真实 gate-1 数据之前）：
  1. 篡改组的条件名被拼成 `tamper_tamper`，判读表里缺篡改组 → 已修。
  2. 篡改目标原来可能选到"被推翻的假设分支里推出、在最终解中不成立"的关系（oracle 桩的对照组有 13.7% 的题出现答案层面 d 在 c 之前）→ 加条件"该关系在最终解 σ 中成立"，覆盖率由 292 变为 **262/500**；单测锁定。

## 需要在登记文本里确认的定义选择（planning-led 的解读，均已写进代码）

1. **N3 主条件 = 禁字母**（`native_letterfree`）：R1/R2/R3 里的 "N3" 指它；N3u = 不禁字母。篡改检验对 N3 用禁字母。
2. **"解析回正确求解步骤"= 与规范推导逐步完全相同**（严格；一条换了等价链的正确推导也算不对）。副报：可解析率、可证率（verify 通过）。
3. **R2a 的"N2s 比 N2 差 ≥5pp"、R2b 的"N3 禁 / 不禁相差 <5pp"按点估计**，不要求显著；R3 "显著更好"对称于 R2（McNemar p<0.05 且 ≥ +5pp）。
4. **R2 子读法恰好命中一个才采用**；命中 0 个或 ≥2 个 → 说不清，停。
5. **TOST 用正态近似、把 1000 个 (题, seed) 配对当独立样本**。同一题在两个 seed 里出现两次（聚类），区间会略窄；可改为按题聚类的 bootstrap——未改，按你的"两个 seed 合并"写。
6. **移植的供体 = 另一题的金标推导（同写法）**，为主；另报用本 run 自己在供体题上生成的 think 段（同 stage-1 E3）。前提 P 用前者。
7. **篡改**：前半 = 去掉 order 后的 ⌊m/2⌋ 步；目标 = 前半中按顺序第一条 force / back 推出的关系，要求在最终解中成立、在前半其后不再作链的一环、在后半某步作链的一环；覆盖 262/500。"续写与被改关系一致" = 续写的链里出现 d→c 且不出现 c→d；另报答案层面 d 是否在 c 前；对照组同样计算作基线。续写预算 = 1024 − 最长前缀 token − 1（统一，mixed 桩下为 896）。
8. **循环** = 同一非空行重复 ≥5 次（金标最多 4 次）。
9. **评估采样 seed 固定为 0**（同 stage-1）；训练 seed 1 / 2 只影响 adapter。
10. A1 的 91.2% 只在报告里作参照，不进任何判读。
